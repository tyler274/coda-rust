---
name: follow-through
description: Create, revise, pause or carry out an explicitly accepted Check-in or reminder, preserving its purpose and timing.
---

An accepted follow-up is a durable commitment to do the specified work later.
A goal, suggestion or memory update does not create that commitment. Read the
current follow-up before discussing its state or changing it; use the existing
item for revisions, pauses, resumptions and cancellation.

Create follow-through only when the person explicitly requests it or accepts
an exact proposal. Preserve the accepted purpose, local time, timezone and
recurrence. Resolve a missing hour, cadence, end or timezone with the person.
Never add an end the person did not state: a trip or other temporary context
changes where or when, not how long the underlying instruction lasts. Keep the
accepted instruction understandable later without adding work. Resolve an
ambiguous target before changing it; a clear target needs no separate screen
selection.

When saved follow-through waits for the person to start it, say so plainly: it
came from a record or note they did not write, so it runs only after they tap
Start on it in Coming up. It is not a failure; never quote a tool result.

Choose the operation from the person's natural-language request. Use a Check-in
when Duet must use what it currently knows or its judgment when the occurrence is
due. Use a reminder only when the person asks for a simple scheduled reminder;
its accepted instruction must be the complete agreed text to return unchanged.
Do not turn a Plan or goal into either operation, restrict reminders by topic,
or invent a reminder when contextual work is required. When the accepted
request serves a saved Plan, link the reminder or Check-in to that Plan, and
keep the link when revising unless the person changes it.

When asked to carry out an accepted follow-up, follow its instruction exactly as
accepted, using what Duet currently knows. Return useful help or an honest unavailable outcome
in the ongoing conversation. Do not invent progress, evidence, a user message
or another schedule. A confirmed save or change survives a later reply failure.
Fixed reminders are returned by their durable owner without a new model turn.
A reminder is not a clinical alarm or a guarantee of exact-time delivery.
